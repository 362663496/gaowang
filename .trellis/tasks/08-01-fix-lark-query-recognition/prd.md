# 修复飞书查询识别

## Goal

让飞书自然语言查询覆盖更丰富的库存业务数据与范围，在模型瞬时异常时可恢复、失败时可诊断，并准确表达用户要求的统计维度。

## Confirmed Evidence

- 所有非空文本统一调用 DeepSeek；`店铺排行` 没有固定命令或本地识别兜底（`apps/api/internal/services/lark.go:205`、`apps/api/internal/services/lark_ai_test.go:163`）。
- 生产配置存在 API Key，模型为 `deepseek-v4-flash`。
- 2026-08-01 20:07:00，“晴朗的店铺今天卖了哪些商品”返回“智能识别暂时不可用”；20:07:26 和 20:07:51 的同一句成功生成 `movement_quantity + group_by=product + shop_keyword=晴朗 + today`。这证明首个失败是瞬时调用或响应问题，而不是固定规则不识别。
- 2026-08-01 20:07:42，“今天销售情况如何？按照商品数量排序，并且列出哪些店铺各占多少”生成单一 `group_by=shop` 计划；现有计划模型无法表达商品 × 店铺二维分组。
- DeepSeek 请求超时、非 2xx、响应解析、截断和计划校验错误全部返回 `errDeepSeekIntent`，解析失败路径没有记录具体阶段（`apps/api/internal/services/lark_ai.go:64`、`apps/api/internal/services/lark.go:219`）。

## Requirements

- L1：保留“所有非空文本走模型、计划白名单校验、本地参数化查询”的安全边界，不增加固定命令抢占。
- L2：网络错误、超时、429、5xx 或计划字段/标签冲突最多再请求一次，整次识别最长 10 秒且总请求不超过两次；响应 JSON 解码错误不重试。
- L3：安全记录失败阶段、HTTP 状态、耗时和消息 ID，不记录 API Key、原始消息或供应商响应正文。
- L4：用户卡片区分服务暂时异常与问题不支持/未理解，不把所有失败混成一个提示。
- L5：多维问题按确认范围生成可验证计划；超出能力时明确说明，不静默降级。
- L6：扩展能力仍由服务端白名单查询计划执行；模型不得生成或执行 SQL，也不得访问账号凭据、备份内容或其他敏感数据。
- L7：数据范围为商品、当前库存、店铺、出入库流水和历史操作人；指标限于数量、笔数、采购成本和库存价值等现有可靠数据。
- L8：支持最多两个分组维度（商品、店铺、操作人中任意组合），覆盖“商品 × 店铺”等自然语言问题；三维及以上明确提示缩小问题。
- L9：支持今天、昨天、本周、上周、本月、上月、本年、最近 N 天、明确起止日期和全部时间，并支持总计、明细、Top/Bottom 排行、按日/月趋势、占比和同期对比。
- L10：结果卡片单次最多展示 10 行，超出时说明结果已截断；不在飞书卡片内一次性倾倒大量明细。
- L11：模型在查询计划中选择 `auto`、汇总、排行、明细、二维分组、趋势或对比等白名单展示意图；服务端校验后用真实结果和现有飞书卡片组件渲染。
- L12：卡片按结果语义突出核心指标、筛选条件与时间范围；无数据、截断、异常和不支持状态分别给出清晰提示。
- L13：模型不得直接提供卡片 JSON、Markdown 数值或最终统计结论；标题、颜色、字段、图片和数值由服务端根据已校验计划与查询结果生成。
- L14：自然语言和安全字段之间不设固定问法白名单；数据范围只开放商品、当前库存、店铺、出入库流水及历史操作人姓名，排除账号字段、权限、审计、备份和系统设置。可从 metric/group_by 确定语义时，服务端纠正 operation/presentation 标签冲突，不丢筛选、维度或时间条件。

## Current Capability Gap

- 当前只有库存数量/价值、流水数量/笔数/采购金额五类指标。
- 当前时间仅支持当前、今天、昨天、最近 1–365 天、本月和全部时间。
- 当前只能按商品、店铺或操作人中的一个维度分组，且分组结果最多 5 行。
- 当前没有明确日期区间、周/年、二维组合、明细列表、趋势、占比或同期对比。
- 当前统计卡片无论查询语义都使用蓝色标题和同一种重复行布局，不能区分汇总、排行、二维结果、趋势与对比。

## Confirmed Decisions

- 接受 L7–L10：扩大库存业务只读查询范围，并继续排除账号、备份、审计数据与任意 SQL。
- 接受 L11–L13：模型选择白名单展示意图，服务端校验并使用真实查询结果渲染卡片。
- 接受一次有限重试和 10 秒总等待上限。

## Acceptance Criteria

- [ ] 同一瞬时错误可按策略重试，成功时正常返回查询卡片。
- [ ] 429/5xx/超时、无效响应和无效计划在日志中可区分，且敏感信息测试通过。
- [ ] “店铺排行”仍经模型生成计划，不引入固定兜底。
- [ ] “按商品排序并列出店铺各占多少”按用户确认的二维范围返回正确结果或明确能力提示。
- [ ] DeepSeek 失败、成功、重试和多维计划均有回归测试。
- [ ] 一次查询的模型调用总时延不超过 10 秒，可重试错误最多发起两次请求，其他错误只发起一次。
- [ ] “今天出库了哪些商品，多少数量”及近似表达返回今日商品出库数量排行；首次计划枚举不合法时可在同一预算内自纠正一次。

## Open Questions

- 无。

## Dependencies

- 前置：`08-01-remove-product-sale-price`，确保飞书指标只使用数量、采购成本和库存价值。
- 前置：`08-01-optional-inventory-notes`，确保新入库/出库备注进入飞书明细和通知验收。
- 集成：`08-01-soft-delete-users`，操作人聚合只展示姓名并保留已删除用户的历史结果。

## Out of Scope

- 不引入第二模型供应商，不保存用户原始消息或模型响应正文。
