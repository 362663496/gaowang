# 库存卡片与流水筛选

## Goal

提升库存操作效率：用响应式商品卡片替代表格，以商品当前价格统一所有金额口径，并让流水记录可按日期范围查询。

## Background

- 当前库存一条 `InventorySnapshot` 对应一个 `ProductID`，现有模型没有独立 SPU/SKU 层级；用户口中的“名称 / 编码”分别对应现有 `Product.Name / Product.Code`。
- 当前库存接口按 `inventory_snapshots.updated_at DESC` 排序；页面表格显示商品图片与名称/编码、数量、移动平均成本、库存金额、状态和更新时间（`apps/api/internal/http/handlers/inventory.go:44`、`apps/web/src/app/(app)/inventory/page.tsx:72`）。
- 现有低库存口径为 `LowStockThreshold > 0 && Quantity <= LowStockThreshold`；阈值为 0 时不判定为低库存（`apps/web/src/app/(app)/inventory/page.tsx:68`、`apps/api/internal/http/handlers/inventory.go:85`）。
- 入库和销售出库表单会在选择商品后预填商品默认进货价/销售价，但价格仍可编辑并随请求提交；后端当前要求 `unit_cents / sale_unit_cents`（`apps/web/src/features/inventory/action-forms.tsx:50`、`apps/web/src/features/inventory/action-forms.tsx:133`、`apps/api/internal/http/handlers/inventory.go:24`）。
- 商品同时保存 `DefaultPurchaseCents` 和 `DefaultSaleCents`；流水会固化采购/销售单价及成本、收入、毛利等派生金额，库存快照另存移动平均成本和库存金额（`apps/web/src/features/types.ts:12`）。
- 流水页和接口目前仅支持类型、商品、店铺筛选，按 `created_at DESC, id DESC` 返回；尚无时间参数（`apps/web/src/app/(app)/stock-movements/page.tsx:24`、`apps/api/internal/http/handlers/movements.go:58`）。

## Requirements

### R1. 当前库存卡片

- 去掉当前库存的数据表格，改为响应式商品卡片网格；每张卡片代表一个现有商品库存快照。
- 列表只显示已有库存快照的商品，包括库存已归零的商品；从未发生库存操作的商品不进入当前库存列表和库存品类统计。
- 每张卡片主要显示商品图片、商品名称、编码、数量、库存金额和状态；移除更新时间。
- 服务端对完整筛选结果先按商品名称升序、再按商品编码升序稳定排序，之后才执行分页。
- 一行卡片数量根据可用宽度自动变化，移动端保持单列可读。
- 保留现有搜索、低库存切换、分页、统计、库存操作和 Excel 导出能力。

### R2. 数量与状态

- 数量为 0 时显示红色“无库存”。
- 数量大于 0 且达到低库存阈值时显示黄色“低库存”。
- 其余商品显示绿色“正常”。
- 卡片的数量颜色与状态颜色保持一致。
- 低库存判定继续沿用当前阈值口径。

### R3. 入库和出库价格

- 商品默认进货价和默认销售价是系统仅有的价格：入库、销售出库、库存调整和流水修订均不接收、校验或展示操作价格。
- “编辑最新流水”移除单价输入及单价变更预览，只保留数量、店铺、备注和修改原因等非价格字段。
- 商品默认价格为 0 时操作仍可执行，对应金额按 0 计算。
- 移动平均成本、入库操作单价、出库操作单价和流水修订单价退出业务计算、输入、展示及预览。
- 当前库存、Excel 导出、历史流水、流水修订预览、仪表盘和全部销售报表中的派生金额均实时读取商品当前价格。
- 商品调价后，所有既有数据的派生金额立即变化；历史收入、成本和毛利不再代表操作发生时的价格。
- 所有金额统一实时派生：
  - 入库金额 = 入库数量 × 商品当前默认进货价。
  - 出库收入 = 出库数量 × 商品当前默认销售价。
  - 出库成本 = 出库数量 × 商品当前默认进货价。
  - 出库毛利 = 出库收入 − 出库成本。
  - 调整金额 = 调整数量 × 商品当前默认进货价。
  - 库存金额 = 当前库存数量 × 商品当前默认进货价。

### R4. 流水时间筛选

- 流水记录增加时间范围筛选，并与现有类型、商品、店铺筛选共同生效。
- 时间筛选变化后回到第一页，结果继续按时间倒序显示。
- 使用按天选择的起止日期范围，默认留空表示全部时间。
- 起止日期均包含整天；例如 7 月 1 日至 7 月 3 日包含这三天的全部流水。
- 日期边界按 `Asia/Shanghai`（UTC+8）解释，与页面展示的北京时间一致。
- 时间筛选依据流水原始业务时间 `CreatedAt`；编辑流水产生的 `UpdatedAt` 变化不改变其日期范围归属。

## Acceptance Criteria

- [x] AC1：当前库存以响应式卡片展示，每个现有库存商品恰好对应一张卡片，桌面宽度增加时自动增加列数，移动端保持可读。
- [x] AC2：卡片显示图片、名称、编码、数量、库存金额和状态，不显示更新时间或表格表头。
- [x] AC3：当前页及跨页数据都按最终确认的名称、编码顺序稳定排列；搜索、低库存筛选和翻页后顺序不变。
- [x] AC4：零库存数量与状态显示红色，低库存显示黄色，正常库存显示绿色；低库存判定结果与现有统计/筛选一致。
- [x] AC5：入库、销售出库、库存调整和流水修订均没有操作单价输入、请求字段或变更预览；商品默认价格为 0 时仍可成功操作。
- [x] AC6：库存页与导出、历史流水、修订预览、仪表盘和销售报表全部按统一公式显示金额；修改商品价格后无需新增流水即可看到既有数据重算。
- [x] AC7：流水可按最终确认的时间范围筛选；时间条件可与类型、商品、店铺组合，清除后恢复全部时间数据。
- [x] AC8：时间筛选依据 `CreatedAt` 和北京时间边界，起止日期均包含整天，编辑流水不会改变其日期归属。
- [x] AC9：现有库存权限、最新流水修订限制、审计、负库存保护、搜索、低库存筛选、分页和导出能力保持有效。
- [x] AC10：前后端自动化检查、前端生产构建及库存/流水关键交互验证通过。

## Out of Scope

- 新增真正的 SPU/SKU 数据模型或迁移现有商品数据。
- 改为门店独立库存或改变店铺在库存流水中的现有语义。
- 重做商品页、仪表盘或报表的列表布局。
- 保存或恢复操作发生时的历史交易价格、批次成本和移动平均成本。
