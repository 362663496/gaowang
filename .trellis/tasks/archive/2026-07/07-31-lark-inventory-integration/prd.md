# 飞书库存集成

## Goal

使用一个企业自建应用机器人，把库存系统的关键操作实时通知到固定飞书群，并允许群成员通过 @机器人快速查询商品和库存，减少频繁打开 Web 后台的需要。

## Background

- 系统已有商品、店铺、库存快照、入库、销售出库、库存调整、流水、权限和审计能力。
- 库存查询已经支持名称/编码搜索、低库存过滤，并按当前商品采购价计算库存金额。
- 商品查询已经支持名称/编码搜索。
- 入库、销售出库和库存调整均通过 `InventoryService` 在事务内更新快照并写入流水；HTTP 层在成功后写审计日志。
- 用户已于 2026-07-31 审阅并批准本 PRD、技术设计与实施计划。

## Requirements

### R1. 机器人与访问范围

- 首期使用一个企业自建应用机器人，不再配置群自定义机器人 Webhook。
- 机器人只服务一个配置好的固定库存群：
  - 系统通知只发送到该群。
  - 只处理该群内的 @机器人消息。
  - 忽略其他群和私聊消息。
- 固定群即首期访问边界，不建立飞书用户与系统账号的映射。

### R2. 实时通知

- 每次成功完成以下操作后发送一张通知卡片：
  - 入库。
  - 销售出库。
  - 库存调整。
- 通知卡片至少显示操作类型、商品名称、编码、数量变化、操作后库存、操作人、时间；有店铺或调整原因时一并显示。
- 低库存定义沿用现有规则：`低库存阈值 > 0` 且 `当前数量 <= 低库存阈值`。
- 当操作使商品从正常库存进入低库存，或从低库存恢复正常时，在同一张操作卡片中突出显示状态变化，避免重复发送两条消息。
- 低库存使用黄色/红色提示，恢复正常使用绿色提示，不 @所有人。
- 飞书发送失败不得改变库存操作的成功结果。

### R3. 群内只读查询

- 首期只支持以下固定命令，不接入大模型或自由自然语言解析：
  - `查库存 <名称或编码>`
  - `查商品 <名称或编码>`
  - `低库存`
  - `帮助`
- 商品名称和编码均支持模糊匹配。
- 未知命令、缺少关键词或不支持的消息类型返回简短帮助说明。
- 查询只返回未归档商品；禁用商品仍可返回，并明确显示状态。
- 查询行为写入审计日志，但不产生库存或商品写入。

### R4. 查询结果

- 唯一结果使用商品卡片，显示图片、名称、编码、当前数量、当前商品采购价、商品售价、库存金额和状态。
- 库存金额始终按 `当前数量 × 当前商品采购价` 计算。
- 多个结果在一条消息中最多展示 5 个。
- 超过 5 个结果时展示前 5 个，并提示缩小关键词。
- 无结果时返回明确的未找到提示。
- 首期不提供翻页按钮或其他需要回调状态的卡片操作。
- 商品图片上传飞书失败时降级为无图卡片，查询本身仍需回复。

### R5. 可靠性与安全

- 使用飞书官方 Go SDK 的长连接接收 `im.message.receive_v1`，无需暴露新的公网回调地址。
- 消息事件在 3 秒内完成接收确认；实际查询与回复通过有界后台队列处理。
- 按 `message_id` 去重，主动发送与回复均使用 UUID 幂等键。
- 通知通过有界后台队列发送，对临时网络错误和限流做有限重试；队列满或最终失败时写进程日志。
- 应用 ID、应用密钥和固定群 `chat_id` 仅通过服务端环境变量配置，不进入前端、审计元数据或日志。
- 仅申请以下最小权限：
  - 以应用身份发送消息。
  - 接收群内 @机器人消息。
  - 上传消息图片。
- 三项飞书配置全部为空时集成保持关闭，便于本地开发和测试；只配置其中一部分时启动失败并给出不含密钥的配置错误。

## Acceptance Criteria

- [ ] AC1：未配置任何飞书环境变量时，API 按现有方式启动且不建立飞书连接；部分配置时配置加载失败。
- [ ] AC2：机器人只处理配置的固定群内 @消息，其他群和私聊不会查询数据库或发送回复。
- [ ] AC3：四个固定命令、缺参、未知命令和非文本消息都有自动化测试。
- [ ] AC4：库存/商品查询支持名称和编码模糊匹配，0、1、2–5、超过 5 条结果均符合展示规则。
- [ ] AC5：唯一商品卡片显示约定字段，库存金额使用当前商品采购价；图片失败可无图降级。
- [ ] AC6：成功入库、销售出库和库存调整各发送一次通知；失败操作和商品资料编辑不发送。
- [ ] AC7：正常→低库存和低库存→正常只在对应操作卡片中提示一次，持续低库存不会重复告警。
- [ ] AC8：飞书超时、限流、断连、队列满或发送失败不回滚库存事务，也不改变原 HTTP 成功响应。
- [ ] AC9：重复 `message_id` 只处理一次；主动消息和回复携带幂等 UUID。
- [ ] AC10：机器人查询写入不含密钥的审计记录，所有日志均不输出应用密钥或访问令牌。
- [ ] AC11：后端格式化、测试和静态检查全部通过，现有库存、流水、权限和审计测试无回归。
- [ ] AC12：部署文档列出飞书应用能力、权限、事件订阅、固定群和环境变量配置，并提供关闭集成的回滚方式。

## Out of Scope

- 私聊机器人或支持多个群。
- 飞书内执行入库、出库、库存调整等写操作。
- 自由自然语言、大模型意图识别。
- 消息卡片翻页、按钮回调或审批流程。
- 商品资料编辑、失败操作通知。
- 日报、周报、定时汇总、告警升级或 @所有人。
- 持久化消息队列和跨重启保证投递。
