# 用户软删除

## Goal

允许管理员从用户列表移除账号，同时保留库存流水和审计历史中的操作人信息。

## Background

- `models.User` 当前有 `Enabled`，但没有删除时间；用户列表响应也不包含启用状态（`apps/api/internal/models/models.go:34`、`apps/api/internal/http/handlers/users.go:32`）。
- 路由只有用户列表和创建，没有删除接口（`apps/api/internal/http/router.go:81`）。
- 登录只接受 `enabled=true` 的账号；现有会话在每次解析时也会检查用户状态。
- `StockMovement.OperatorID` 对用户使用 `RESTRICT`，审计日志同样需要保留操作者，因此物理删除不适用。

## Requirements

- U1：新增管理员可用的用户删除操作，数据库记录采用显式软删除时间并同时禁用账号。
- U2：删除事务必须撤销该用户全部会话；用户权限不再生效。
- U3：默认用户列表隐藏软删除账号，历史流水与审计仍能解析原用户姓名。
- U4：禁止删除当前登录账号，并保护系统至少保留一个可用管理员。
- U5：成功和失败均使用现有 API 错误契约；成功写入审计记录。
- U6：用户页提供危险操作确认和提交期间防重复操作。
- U7：软删除后的用户名和邮箱继续占用唯一身份，不允许新账号复用；本次不增加已删除列表或恢复入口。

## Acceptance Criteria

- [ ] 删除普通用户返回成功、列表不再显示、旧会话立即失效、重新登录失败。
- [ ] 历史库存流水和审计记录仍展示被删用户。
- [ ] 删除自己或最后一个可用管理员返回冲突错误且数据不变。
- [ ] 删除不存在或已删除用户返回稳定的未找到错误。
- [ ] 相关后端测试、前端 lint/类型检查和页面测试通过。

## Open Questions

- 无。

## Dependencies

- 无前置子任务；与飞书子任务集成时，历史流水中的已删除操作人姓名必须继续可查。

## Out of Scope

- 用户恢复、永久删除或批量删除。
