# 飞书机器人查询体验升级

## Goal

让固定库存群成员直接用日常中文查询库存，避免关键词或狭窄意图误判；统计问题可自由组合商品、店铺、操作人、指标和时间范围，所有包含具体商品的回复都展示对应图片。

## Background

- 当前 `查商品` 会包含尚无库存快照的商品，`查库存` 只包含已有库存快照的商品；除此之外，两者搜索、排序与展示字段相同，保留两个入口的价值很低。
- 当前仅唯一商品结果会尝试附带图片，多商品结果为纯文本。
- 现有商品、库存快照和流水数据已经足够支持概览、低库存、最近流水与当日变动，无需新增数据表。
- 单纯扩大意图枚举仍会把“哪个店铺出货最多”误判成商品销售排行；统计能力应由受控查询维度组合，而不是每种问法一个 intent。
- 机器人继续只服务一个配置群，并保持只读。

## Requirements

### R1. 全量自然语言识别

- 去掉本地固定短语/首词识别；任何去除机器人提及后的非空文本都只交给 DeepSeek 解析一次，包括“查库存”“帮助”等短句。
- 非文本或去除提及后为空的消息只返回帮助，不请求模型。
- 商品查询模糊匹配全部未归档商品；没有库存快照的商品按数量 0 展示。
- 保留库存查询、低库存、库存概览、流水和今日变动，并新增：
  - `缺货清单`：列出数量小于等于 0 的未归档商品。
  - `库存金额排行`：按当前数量 × 当前商品采购价倒序列出有库存商品。
  - `今日销售排行`：按上海自然日销售出库数量汇总并倒序列出商品。
- 将库存金额排行、销售排行以及店铺/操作人统计统一接入可组合统计查询计划；现有展示行为保持兼容。
- 帮助卡片只给大白话示例，不再区分固定命令。

### R2. 商品图片

- 任何回复只要包含一条或多条具体商品信息，每条商品信息都应显示自己的商品图片。
- 库存、低库存、缺货、金额排行、销售排行和流水最多返回 5 条；多结果放在一张卡片中，图片与对应文字相邻。
- 图片使用紧凑缩略图布局，不再横向铺满整张卡片；图片不能压过商品名称、数量和库存状态等核心信息。
- 商品无图片、图片文件缺失或上传飞书失败时，只降级该商品的图片，文字结果仍正常返回。

### R3. 卡片信息层级

- 库存操作通知和查询卡片都要区分主次：商品名称、编码、数量变化、库存结果和状态为主要信息，操作人、时间、店铺和原因作为次级信息。
- 关键数字使用粗体，并配合语义色标题和状态符号：入库/增加为绿色，出库/减少为红色，低库存为橙色，普通说明保持中性。
- 字段采用分组或双列布局，避免连续文本堆叠；编码继续使用等宽样式，时间保持易读的上海时区格式。
- 商品卡片把库存数量放进商品主信息区，以图标、单位和粗体单独强调，不再藏在短字段网格中。
- 商品信息只展示当前采购价，不展示商品售价；库存金额仍为数量 × 当前采购价。

### R4. DeepSeek 自然语言查询计划

- 所有非空文本统一请求 DeepSeek，本地不再按命令前缀短路。
- 使用 DeepSeek 官方 Chat Completions API、`deepseek-v4-flash` 非思考模式和 JSON Output；模型名可通过服务器环境变量覆盖。
- 商品详情、低库存、缺货、库存概览、流水明细、今日变动、帮助和无法识别保留少量明确入口；统计类统一返回 `analytics` 查询计划。
- 查询计划只允许组合：`metric`、`group_by`、`movement_type`、`time_range`、`days`、`sort`、`limit` 以及商品/店铺/操作人筛选词。
- 支持指标：当前库存数量、当前库存金额、流水数量、流水笔数、流水金额；支持按商品、店铺、操作人或不分组汇总。
- 支持时间：当前、今天、昨天、近 N 天、本月、全部历史。流水未说明时间时默认全部历史，当前库存指标固定使用当前值。
- 至少覆盖 40 条代表性日常中文测试语料，包含不同维度、指标、流水类型、时间和筛选组合。
- AI 只接收去除机器人提及后的用户文本，不接收库存数据、凭证、聊天历史或数据库结构；不保存多轮对话状态。
- 系统严格校验 AI 返回的 JSON、枚举组合、筛选词长度、天数和条数；AI 不能生成 SQL、调用写操作或决定金额与库存结果。
- DeepSeek API Key 仅通过服务器环境变量配置，不进入仓库、日志、审计或飞书回复。
- DeepSeek 未配置、超时、限流、异常、空响应或非法输出时返回简短降级提示，不尝试本地猜测，不影响长连接与后续消息。

### R5. 查询与访问边界

- 商品结果继续按名称、编码、ID 稳定排序，最多 5 条，超出时提示缩小关键词。
- 低库存沿用 `阈值 > 0` 且 `数量 <= 阈值`，无库存快照视为数量 0。
- 缺货使用 `数量 <= 0`；库存金额排行只包含数量大于 0 的商品，金额相同时按名称、编码、ID 稳定排序。
- 今日销售排行只汇总上海当日销售出库，按售出数量倒序、名称、编码、ID 稳定排序。
- 流水按创建时间、ID 倒序，显示商品、类型、数量变化、操作人、店铺（如有）和时间。
- 所有金额始终使用当前商品采购价计算。
- 统计排行最多返回 5 条；“哪个/最高”可返回 1 条。相同指标值按名称、ID 稳定排序。
- 流水数量按类型归一：入库为正数量，销售出库取绝对数量，调整保留正负净变化；全部类型表示库存净变化。
- 按店铺或操作人分组时只统计有关联对象的流水；商品历史统计继续保留归档商品。
- 商品、店铺和操作人筛选均使用参数化模糊匹配；模型字段只参与本地枚举分支，不拼接 SQL。
- 仅处理配置群内真实 @机器人的消息；其他群、私聊、@所有人和重复消息继续被拒绝。
- 每次成功解析均写入不含凭证和原始模型响应的审计记录。

## Acceptance Criteria

- [x] AC1：所有非空文本（含看似固定命令的短句）都调用一次 DeepSeek；本地没有短语优先级或迁移分支。
- [x] AC2：单商品、多商品、低库存、缺货、金额排行、销售排行和流水结果中的每条具体商品均带对应紧凑缩略图；单张图片失败只影响该图。
- [x] AC3：商品卡片主区显眼显示库存数量，只显示采购价而不显示售价；操作通知与其他查询卡片继续保持清晰层级。
- [x] AC4：库存概览、流水、今日变动、缺货清单和可组合统计的范围、排序、上限、空结果均有自动化测试。
- [x] AC5：至少 40 条代表性日常中文覆盖全部入口及统计计划组合，并限制筛选词、天数和条数。
- [x] AC6：未知意图、非法 JSON、非法枚举/组合、空响应、非 2xx、超时和未配置 Key 均安全降级，不进行本地猜测。
- [x] AC7：DeepSeek 请求不包含库存数据、凭证或历史消息；日志、审计和错误信息不包含 API Key 或原始模型响应。
- [x] AC8：固定群、提及、去重、只读查询、有界队列和飞书发送失败隔离规则保持不变。
- [ ] AC9：Go 格式化、完整测试和静态检查通过；部署后自然语言、图片、卡片样式、新增排行/清单与降级路径在新库存群完成回归验证。
- [x] AC10：“哪个店铺出货最多”解析为全部历史、销售出库数量、按店铺倒序取第一名；不得触发商品销售排行。

## Out of Scope

- 库存以外的通用 AI 问答。
- 飞书内执行入库、出库、调整或其他写操作。
- 多群、私聊、用户身份映射或多轮上下文记忆。
- 定时日报、交互按钮、卡片回调或新增数据库表。
- 模型生成 SQL、任意字段访问或绕过本地只读查询构建器。
