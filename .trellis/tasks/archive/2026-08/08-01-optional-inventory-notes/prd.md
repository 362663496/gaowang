# 出入库可选备注

## Goal

允许操作人在新增入库或销售出库时填写可选备注，并让备注随流水保存和展示。

## Background

- `StockMovement.Reason` 已承载调整原因及流水备注，流水列表、修订、飞书通知和飞书流水卡片已有展示逻辑。
- 当前入库和销售出库请求、服务输入及前端表单没有备注字段，只有库存调整要求必填原因。

## Requirements

- N1：`POST /inventory/inbound` 和 `POST /inventory/sales-outbound` 接受可选 `note` 字符串。
- N2：备注去除首尾空白，空白内容按未填写处理，最多 500 个字符；超限请求不得产生库存或流水变更。
- N3：服务层将有效备注写入新流水的 `Reason`，保证非 HTTP 调用也遵守长度约束。
- N4：入库和销售出库弹窗各增加“备注（可选）”文本框，不影响原有必填字段和库存校验。
- N5：非空备注随流水列表、流水修订和飞书通知/查询展示；现有库存调整原因仍保持必填。
- N6：成功审计仅在备注非空时增加 `note` 元数据，不改变现有 action 和资源标识。

## Acceptance Criteria

- [ ] 省略、空字符串或纯空白备注时，入库和销售出库均按原流程成功且流水备注为空。
- [ ] 合法备注被规范化后持久化，并在流水列表和飞书卡片中显示。
- [ ] 超过 500 字符返回稳定 400 错误，库存快照、流水和审计均不变化。
- [ ] 调整操作仍要求原因，最新流水修订行为不变。
- [ ] 后端测试、前端 lint/类型检查、测试和构建通过。

## Dependencies

- 前置：`08-01-remove-product-sale-price`，两者都会修改销售出库服务、流水类型和库存操作页面，按顺序实施以避免契约冲突。
- 集成：`08-01-fix-lark-query-recognition`，飞书明细与通知应继续展示新备注。

## Out of Scope

- 不增加备注模板、必填规则、富文本、附件或独立备注表。
