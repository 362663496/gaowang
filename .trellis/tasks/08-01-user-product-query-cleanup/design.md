# 技术设计：用户、商品与飞书查询整合

## 设计目标

四个交付物分别实现、分别验证，最后以同一 API/Web 版本集成发布。父任务不新增业务抽象，只维护跨任务契约、执行顺序和发布回滚边界。

## 子任务边界

| 子任务 | 数据层 | API/服务层 | 用户界面 |
| --- | --- | --- | --- |
| 用户软删除 | `users.deleted_at`，保留历史外键 | 删除事务、会话/权限撤销、查询过滤 | 用户列表危险操作 |
| 移除销售价 | 停止映射销售价及收入/毛利字段，生产旧列保留 | 销售出库只计算采购成本，报表按数量/成本 | 商品、流水、仪表盘、报表去除销售额/毛利 |
| 出入库备注 | 复用 `stock_movements.reason` | 入库/销售出库接受可选备注 | 两个库存操作弹窗增加备注 |
| 飞书查询 | 无新业务表 | 扩展受控查询计划、重试诊断、多维查询、卡片渲染 | 飞书回复卡片 |

## 执行顺序与依赖

1. 用户软删除独立完成并验证历史关联。
2. 移除商品销售价，先确定最终可用指标与 API 类型。
3. 出入库可选备注复用已收敛后的流水服务与类型。
4. 飞书查询在第 2、3 步的契约上扩展，禁止重新引入销售额或毛利，并保留备注展示。
5. 集成验证软删除操作人在流水、审计及飞书历史统计中仍显示姓名。

## 跨层契约

- 所有写操作继续经过现有权限、中间件、同源校验和稳定错误信封。
- 用户、商品和流水响应均使用显式安全 DTO 或已收敛模型，不暴露密码、已停用财务字段或模型供应商内容。
- 金额只保留当前采购价、采购金额、销售出库估算成本和当前库存价值，均为整数分。
- 飞书模型只输出白名单计划；数据库查询由本地固定表达式和参数绑定执行。
- 卡片中所有业务数值来自数据库结果，模型只选择展示意图。

## 兼容与迁移

- `users.deleted_at` 由现有 `AutoMigrate` 新增；使用显式可空时间而非 GORM 隐式软删，历史关联默认仍可预加载。
- 生产库已有 `products.default_sale_cents` 及流水收入/毛利列不执行删除，供旧版本回滚和历史核对；新运行时代码不映射、不读写、不展示。
- 旧前端若仍提交 `default_sale_cents`，multipart 解析会忽略额外字段；新前后端同步发布后响应不再包含该字段。
- 报表路由和已有权限键保持不变，响应字段从销售额/毛利收敛为数量、笔数和采购成本，避免迁移持久化权限。

## 发布与回滚

- 本地完成 Go、Web、GitNexus 影响检查和全量构建后，提交并推送同一版本。
- 按 `.trellis/spec/deployment/aliyun-release.md` 在切换前备份 PostgreSQL，上传本地构建的不可变发布包并原子切换。
- 回滚只切回上一发布并重启两项服务；新增 `deleted_at` 和保留的旧财务列对旧版本均为兼容扩展。
- 回滚后，已软删用户仍为 `enabled=false`；新版本期间创建的商品/销售流水在旧财务列中保持数据库默认零值，不伪造销售收入。

## 主要风险与控制

- 并发删除管理员：事务锁定目标及可用管理员集合，再判断最后一个管理员。
- 财务语义残留：对 `apps/api` 和 `apps/web` 做字段级扫描，并以 API/页面回归测试确认无销售额/毛利。
- 模型扩展后错误查询：严格枚举计划、最多二维、固定查询表达式、10 行展示上限。
- 模型故障拖慢回复：一次条件重试，10 秒总截止，预留外层 20 秒任务上下文给查询和发卡。
